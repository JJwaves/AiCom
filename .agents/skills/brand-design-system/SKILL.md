# Brand design system

Inspect the target project's AGENTS.md, DESIGN.md, package manifest and existing UI before proposing changes. Preserve existing settings and brand decisions. If no project is supplied, prepare a reusable design contract only.

Use [assets/DESIGN.md](assets/DESIGN.md) as the starting contract for a US restaurant takeout-bag supplier. Copy it into a new project's root only when requested and when DESIGN.md is absent; otherwise propose a focused merge. The template is an editable default, not an established brand or verified product specification.

Establish audience, actual product materials, real photography and primary conversion. Prefer “Request a quote” and “Request samples” when bulk prices depend on specification. Write US English customer copy; discuss work in the user's language.

Use one visual direction: warm editorial utility, tactile product photography, strong type hierarchy and restrained color. Adapt the structure of Awesome DESIGN.md (tokens, component rules, layout, responsive behavior), not another brand's identity, logo or proprietary fonts. Existing user-approved design choices take priority.

Define semantic colors, type scale, spacing, container widths, borders, radii, focus, motion and image treatments before component styling. Map the tokens to the project's existing Tailwind/CSS setup; do not replace its configuration or install frameworks as part of brand definition.

Read [references/sources.md](references/sources.md) for provenance and [references/reviewed-design-principles.md](references/reviewed-design-principles.md) for the vetted Taste/minimalist subset. Output the contract, decision rationale and unresolved product facts. Do not invent sustainability certifications, customers, claims, prices or lead times.
